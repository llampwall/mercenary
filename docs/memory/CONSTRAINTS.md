# Constraints

## Infrastructure
- Runtime: Node.js 22+ ESM (`"type": "module"` in package.json)
- Single file: `mercenary.js` — no build step, no bundler
- Zero external dependencies — Node.js stdlib only
- Windows-only: depends on `wt` (Windows Terminal) and `pwsh` for interactive mode
- Process tree kill via `taskkill /T /F /PID` — no Unix `kill` signal chains
- Canonical project memory: `docs/project_notes/` (ADR-001); `docs/memory/` is legacy/non-canonical
- Windows CLI arg limit: 32,767 chars; `run()` switches to stdin piping when `estimateArgLength(spawnArgs) > 20K` (`SAFE_CLI_CHARS`) to avoid truncation (added 2026-03-06)

## Rules
- Always set `--dangerously-skip-permissions` on every spawned claude process (updated 2026-02-25)
- `--no-session-persistence` applies only to one-shot `-p` launches; do NOT pass it to `openSession()` interactive sessions (updated 2026-02-25)
- Always delete `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT`, `ANTHROPIC_API_KEY`, `CLAUDE_CONFIG_DIR` from child env — exception: in local-model branch, `CLAUDECODE` and `CLAUDE_CODE_ENTRYPOINT` are PRESERVED to match the env shape of an interactive CC session (updated 2026-07-09)
- Force `SHELL=pwsh` in `sanitizeEnv()` and in `openSession()` launcher to prevent PM2-inherited bash.exe (updated 2026-02-25)
- Use `shell: false` with resolved claude binary path — never rely on shell PATH lookup
- `pipeline` role uses `--strict-mcp-config` only; no `mcp-none.json` fallback injected (global mcpServers is empty) (updated 2026-02-26)
- Interactive sessions (`openSession()`) must NOT use `--strict-mcp-config` — causes Claude to hang silently; default `strictMcp: false` for interactive. ONE exception: when `useLocalModel` is set, `strictMcp` defaults to `true` with no `--mcp-config`, so nothing loads (updated 2026-09-05, was 2026-02-25)
- Interactive local-model sessions emit `--tools Read,Edit,Write,Glob,Grep,PowerShell` (`LOCAL_MODEL_INTERACTIVE_TOOLS`, mercenary.js:36) — the built-in Artifact tool is interactive-only and its JSON schema defeats llama.cpp's grammar converter, failing every turn with `400 Failed to initialize samplers: failed to parse grammar`; `opts.tools` and `opts.strictMcp` still override, and non-local interactive sessions emit neither flag (added 2026-09-05)
- Each `openSession()` must set child `TEMP`/`TMP` to its mkdtemp dir to prevent EINVAL from shared task output directory collisions (updated 2026-02-25)
- Automation scripts must live in `scripts/` or `tools/`
- LF line endings everywhere; only `.bat` and `.cmd` may use CRLF (enforced by `.editorconfig` and `.gitattributes`)
- Multiline content edits must use direct file edits — no ad-hoc Python/regex replacement scripts
- When `--resume <id>` is used, `--no-session-persistence` must NOT be passed (resume requires session persistence) (updated 2026-03-05)
- `--session-id <uuid>` strips `--no-session-persistence` and passes `--session-id <uuid>` to claude CLI; same session-persistence pattern as `--resume` (added 2026-03-12)
- Use `appendSystemPrompt`/`--append-system-prompt` for persona injection; only use `--system-prompt` when the full default system prompt must be replaced (updated 2026-03-05)
- Codex one-shot defaults: `--dangerously-bypass-approvals-and-sandbox --ephemeral` unless `sandbox` is explicitly provided (added 2026-03-08)
- On Windows, `resolveCodexPath()` attempts to resolve the native `.exe` via `resolveCodexNativeExecutable()` before falling back to the `.cmd` shim — never spawn the `.cmd` shim when `.exe` is available; `resolveCodexNativeExecutable()` probes both `vendor/<triple>/bin/codex.exe` (current layout) and `vendor/<triple>/codex/codex.exe` (legacy layout) (updated 2026-06-04)
- `shouldDisableCodexMcp(opts, mode)` controls per-run MCP disable for Codex: pipeline/streaming/allmind one-shot default to disabled; coordinator/allmind interactive default to disabled; explicit `opts.disableMcp` overrides all (added 2026-03-07)
- `getDefaultCodexSandbox(opts, mode)` sets sandbox default: pipeline/streaming one-shot → `workspace-write`; coordinator interactive → `workspace-write`; others → none (added 2026-03-07)
- `repo-agent` role is a pipeline alias: identical behavior (stream-json, `--strict-mcp-config`, MCP disabled, `workspace-write` sandbox for Codex) (added 2026-03-11)
- When `dispatchId` is passed to `openSession()`, the launcher sets `$env:ALLMIND_DISPATCH_ID` in the child env and POSTs `mercenary_session_exit` to AllMind `/api/internal/event` after Claude exits; exit hook POST body includes `thread_id` in details when spawned with an origin thread; a fire-and-forget background job also finds the real `claude.exe` PID (Get-CimInstance child of launcher $PID, name claude*) and POSTs to `/api/internal/ledger/update-pid` — on failure the ledger retains the launcher PID (updated 2026-06-27)
- All spawn paths (`run()`, `openSession()`, `openHeadlessSession()`) warn to stderr when `purpose` or `origin` are not provided — callers must supply both for traceability (added 2026-03-21)
- `appendSystemPrompt` content >8K chars must be written to a temp file; use `--append-system-prompt-file <path>` (or `--system-prompt-file`) instead of inline flag to avoid Windows ENAMETOOLONG / CLI arg truncation — applies to ALL spawn paths (`run()`, `openSession()`, `openHeadlessSession()`); never load temp file content back into a PowerShell variable and expand inline (updated 2026-04-28)
- When `useLocalModel` is set on a spawn, `ANTHROPIC_BASE_URL` and `ALLMIND_LOCAL_MODEL=1` are both injected into the child env; other spawns are unaffected (updated 2026-04-30)
- Never set `ANTHROPIC_AUTH_TOKEN` on local-model spawns — flips Claude into API-billing mode which trips the enterprise sandbox gate on Windows (added 2026-05-08)
- Never set `ANTHROPIC_MODEL` env var on local-model spawns — empirically ignored on 2.1.132 for model selection but triggers API-billing banner; use `--model` flag instead (added 2026-05-08)
- `sanitizeEnv()` strips `ANTHROPIC_MODEL` defensively on all spawn paths (added 2026-05-08)
- Both launcher.ps1 templates (run + openSession) must explicitly null `ANTHROPIC_AUTH_TOKEN` and `ANTHROPIC_MODEL`, and set `CLAUDE_CODE_USE_POWERSHELL_TOOL=1` + `CLAUDE_CODE_REMOTE=1` for local-model spawns (added 2026-05-08)
- `data/claude-local-model-settings.json` is injected via `--settings` for all local-model spawn paths; `--local-model-settings-path` CLI flag overrides the default path (added 2026-05-08)
- Only one `--settings` may be passed per spawn: `opts.settingsPath` and the local-model profile's own settings file are mutually exclusive, and local-model wins (`else if` at all three arg builders — `buildArgs`, `openSession()` launcher, `openHeadlessSession()`) (added 2026-08-17)

The crash no longer reproduces on the current Claude Code CLI — a qwen-lane session (dispatch qwen-1786228741458-921ac9) ran git status/add/commit via the PowerShell tool without error. - `buildCodexArgs` always passes `--model` explicitly; never rely on the Codex CLI's built-in default — it changes between Codex versions and may be rejected with "requires newer version of Codex"; pinned default is `gpt-5.5` (confirmed on Codex CLI 0.133.0) (updated 2026-06-04)
- `opts.initialMessage` in `openSession()` (both claude and codex interactive launchers) is written to `initial-message.txt` in the spawn tmpdir, loaded via `Get-Content -Raw` into a PS variable, then passed as a bare positional arg. (Codex's `developer_instructions` used the same pattern until 2026-08-19; it now ships via a profile file — see the profile bullet below.) This is a deliberate, narrow exception to the "never load temp file content back into a PS variable" rule below: it exists to dodge PowerShell string-escaping bugs (live backticks, `$` interpolation) in the old inline double-quoted form, not CLI length — safe only because initial messages/dev instructions are expected to stay well under the argv length ceiling; large content (e.g. system prompts) must still use the `-file` flag variant (added 2026-07-07)
- `run()` spawns must use `detached: false` for BOTH backends — on win32 libuv's DETACHED_PROCESS overrides the CREATE_NO_WINDOW that `windowsHide` asks for (node#21825), so the child has no console and its own spawns pop visible windows: codex's pwsh/git helper cascade, and for claude Claude Code's startup `cmd /c REG QUERY ... MachineGuid` (one cmd.exe popup per headless session, confirmed by eye 2026-09-02, 3/3 detached vs 0/3 hidden). Nothing needed `detached`: treeKill is by PID, and a Windows child outlives its parent without it (updated 2026-09-02, was codex-only 2026-06-05)
- Every spawn must stamp `ALLMIND_AGENT_SESSION` into the child env at the env-builder boundary — `sanitizeEnv` (headless claude), `sanitizeEnvCodex` (codex), `buildLauncherEnvLines` (interactive) — never per-caller; stamping at callers cannot converge (one caller reached 7 of 46 spawn sites) (added 2026-08-01)
- The agent-session stamp runs AFTER the `opts.env` merge: a caller may NAME the session by passing the marker through `opts.env`, but a blank/whitespace value cannot suppress it — it falls through to `opts.dispatchId`, then to a locally minted id; case-variant spellings of the key are collapsed to the canonical `ALLMIND_AGENT_SESSION` (added 2026-08-01)
- All three env builders strip model/endpoint routing vars — `sanitizeEnv()`, `sanitizeEnvCodex()`, and `buildLauncherEnvLines()` (interactive PS1 nulls) — covering `ANTHROPIC_BASE_URL`, `ANTHROPIC_SMALL_FAST_MODEL`, `CLAUDE_CODE_SUBAGENT_MODEL`, `API_TIMEOUT_MS`, `ALLMIND_LOCAL_MODEL`, `CLAUDE_CODE_REMOTE`, and any `ANTHROPIC_DEFAULT_*` key (case-insensitive prefix, JS builders only — the PS1 block nulls the named vars, not the prefix); mirrors allmind `lib/claude-env.js` MODEL_ROUTING_VARS; strips run BEFORE the local-model profile and the `opts.env` merge, so only a deliberate opt-in re-sets routing. The launcher re-sets `CLAUDE_CODE_REMOTE=1` immediately after nulling it, deliberately (added 2026-08-02, extended to codex + launcher 2026-08-22)
- Every local-model claude launch (one-shot, headless stream, interactive launcher) carries `--thinking-display summarized` and NEVER disables thinking: Claude Code adds `thinking.display: "omitted"` to non-interactive text/json sessions and NInfer rejects that value with a 400, while an explicit "summarized" is accepted by every rig with thinking on. Disabling thinking also clears the 400 but zeroes the engine's thinking tokens — a nerf, reverted 2026-09-12 by operator ruling (added 2026-09-12)
- `opts.initialMessage` over `SAFE_CLI_CHARS` (20K) must NOT ride argv in either interactive launcher — `pushInitialMessageLine()` writes `initial-message.txt` always, and over the threshold puts a short pointer in `$mercInitialMessage` telling the agent to read the file; interactive mode has no stdin fallback (piping stdin drops the session out of interactive) (added 2026-08-22)
- Large codex `developer_instructions` must NEVER go through argv (`--config developer_instructions=...`) — the block runs tens of KB and Windows caps a command line at 32,767 chars, so CreateProcess fails before codex starts. BOTH codex paths deliver it via a profile file written as a TOML literal `'''` multiline string (any `'''` in the content is broken to `'' '`) and named with `--profile <name>`: `openSessionCodex` writes `$CODEX_HOME/merc-<session>.config.toml` and the launcher removes it after exit; `buildCodexArgs` (one-shot) writes `$CODEX_HOME/merc-oneshot-<pid>-<ts>.config.toml` when the block exceeds 8000 chars and `run()` owns its lifetime (removed on close, on spawn error, and when the stdin-prompt rebuild orphans an earlier one). Blocks under 8000 chars stay on argv. Caller-supplied `-c`/`codexConfigOverrides` still win over the profile (updated 2026-09-01, added 2026-08-19)
- Interactive codex sessions must set an approval policy, not just a sandbox: sandboxed → `--sandbox <s> --config approval_policy="never"`, unsandboxed → `--dangerously-bypass-approvals-and-sandbox`. Codex's default is `on-request`, which stalls a dispatched session waiting on human approval (added 2026-08-19)
- Both interactive launchers (claude and codex) must build only their own env block + invocation args and then hand off to `finishInteractiveLauncher()` for the shared tail (`opts.launch` hook, ledger PID phone-home, exit hook, cleanup) — never re-implement the tail per backend; the codex copy silently missed every feature added since it was forked (added 2026-08-19)
- Launcher exit hooks must read `$mercExitCode` (`$LASTEXITCODE` defaulted to `-1` when null), never `$LASTEXITCODE` directly — a launch that never ran a native command leaves it null, which produces invalid JSON and crashes the AllMind event endpoint's parser; `-1` means "never launched" (added 2026-08-19)
- Local-model spawns set `CLAUDE_CODE_MAX_OUTPUT_TOKENS=16384` in `sanitizeEnv()` unless the caller passes `opts.maxTokens` — the Anthropic-scale 65536 arrives verbatim as the rig's `n_predict`, and at ~30 tok/s that is an unbounded compaction summary (added 2026-08-19)
- `data/claude-local-model-settings.json` must pin every child setting whose machine-wide default is tuned for Anthropic models — inherited values reach the rig verbatim; currently pinned: `effortLevel: "medium"` (the rig chat template 400s on `high`), `autoCompactWindow`, `precomputeCompactionEnabled` (added 2026-08-31)
- `/update-memory` must NOT commit an anchor-advance when the only uncovered commits are docs-only (`docs:`/`notes:` prefix, or touching only `docs/memory/`, `docs/project_notes/`, `CLAUDE.md`, `AGENTS.md`) — each such commit becomes the next run's uncovered commit, producing an infinite churn loop; leave the anchor where it is and report "up to date" (added 2026-07-23)

## Hazards
- `--interactive` silently fails if `wt` or `pwsh` are not installed/discoverable on PATH
- Built-in claude binary path is user-specific; set `CLAUDE_PATH` env var on other hosts
- Placeholder CI always reports green — runtime regressions can go undetected
- Integration tests are skipped unless `MERCENARY_INTEGRATION=1` is set — easy to miss real breakage
- `--strict-mcp-config` in interactive (`openSession`) mode causes Claude to hang silently without error — interactive must use `strictMcp: false` (updated 2026-02-25)
- Without MCP suppression, pipeline/coordinator spawns can generate ~40 conhost popup windows on Windows (updated 2026-02-25)
- Passing `--no-session-persistence` to `openSession()` (interactive) crashes or misbehaves — only valid for `-p` one-shot mode (updated 2026-02-25)
- Claude Code 2.1.88+ requires stdin input within ~3s when using stream-json pipe mode (`openHeadlessSession()`); failing to send stdin quickly enough causes a silent startup hang (added 2026-04-17)
- PowerShell launcher: writing a prompt to a temp file then loading it back with `Get-Content` and expanding inline (`--flag $content`) defeats the purpose — PowerShell expands the variable into argv at CreateProcess(), hitting the Windows CLI length limit; always pass the file path via the `-file` flag variant (added 2026-04-28)
- RETIRED 2026-08-08: Local-model `openSession()` on win32 Qg7 shell-gate hazard — the crash no longer reproduces on the current Claude Code CLI, so shell-needing work in an interactive local-model session no longer needs to route through `run()` / `openHeadlessSession()`; the no-shell gate was removed (see the RETIRED constraint above and the 2026-08-08 decision). If the crash resurfaces on a CLI update, revert the retirement commit (updated 2026-08-08, was added 2026-05-08)
- `ANTHROPIC_AUTH_TOKEN=not-needed` (or any value) flips Claude Code into API-billing mode on Windows — the enterprise sandbox gate fires and the session fails; never set this env var for local-model spawns (added 2026-05-08)
- `Read-Host` or any interactive pause in a generated launcher.ps1 blocks every `openSession()` dispatch — the terminal window waits for operator Enter and the session never progresses; never leave diagnostic pauses in launcher templates (added 2026-05-09)
- Codex CLI's built-in default model changes between versions; `buildCodexArgs` pins `gpt-5.5` (confirmed on Codex CLI 0.133.0) and always passes `--model` — if a future release rejects this, bump `DEFAULT_CODEX_MODEL` and validate before deploying (updated 2026-06-04)
- `.cmd` test helper scripts fail with EINVAL when spawned with `windowsHide: true` + `detached: true` on Windows; use `.js` helpers via `node` instead (added 2026-05-18)
- On win32, `windowsHide` is silently dropped when `detached: true` (node#21825) — every `run()` spawn (claude and codex) uses `detached: false` so `windowsHide: true` is honored and the child gets a hidden console its whole tree inherits; treeKill still works via `taskkill /T /F /PID` (updated 2026-09-02 to cover claude, was codex-only 2026-06-05)
- A leaked `ANTHROPIC_BASE_URL` in the parent env (AllMind local-model lanes set it) silently routes spawned sessions to the local endpoint with no error — all three env builders (`sanitizeEnv`, `sanitizeEnvCodex`, `buildLauncherEnvLines`) now strip the routing set, closing the interactive and codex gaps; any NEW env builder must repeat the strip or it reopens the hole (updated 2026-08-22, added 2026-08-02)
- Writing a launcher value to a temp file and loading it back with `Get-Content -Raw` fixes PowerShell string mangling but NOT length — the variable still expands into the CreateProcess command line and dies at the Windows 32,767-char cap. Any launcher value that can grow unbounded needs a length guard (file pointer or profile file), not just the temp-file round trip (added 2026-08-22)
- `readLedger()` rethrows on malformed JSON — only `ENOENT` is caught (mercenary.js:412) — so a corrupted `.process-ledger.json` crashes `--ps`/`--audit`/`--purge` outright, while spawn paths survive silently (their `ledgerRegister` calls are individually try/caught) and just stop tracking processes; recovery is manual — move the file aside as `.process-ledger.json.corrupt-YYYYMMDD` (gitignored since 6dba9c8) and mercenary recreates it.
